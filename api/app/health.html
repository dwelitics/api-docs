GET /api/health

What it does

Returns the identity of the build currently answering on this host, and nothing else. git_sha, app_version (the package.json semver), human_version (CalVer YYYY.MM.DD-<sha7>) and build_time are baked at build time by scripts/stamp-version.mjs; env and vercel_deployment_id are read from the Vercel runtime environment; ts is Date.now() at the moment of the request.

question_cache reports whether KV_REST_API_URL and KV_REST_API_TOKEN are present on THIS deployment, which decides whether Metabase reads are cached or go live to Snowflake on every page. It was off on every preview for months and nothing showed it, because a disabled cache renders exactly the same page as a working one — so the state is exposed here instead of being inferred from a log nobody reads.

The response always carries Cache-Control: no-store, and the route is dynamic = 'force-dynamic'. A cached health check answers for the build that used to be there.

What it does not do

  • No database, no AI, no Metabase call. question_cache reports the configuration, it does not probe the cache. A 200 here says the function booted; it does not say Supabase is up. (A Supabase management API once reported ACTIVE_HEALTHY over a database answering nothing — DISC-288. This route makes the same class of claim about itself: build identity, not dependency health.)
  • No 4xx, no 5xx, no error branch. The handler has exactly one path. If you get a non-200 from this route, it came from the platform in front of it, not from this code.
  • It does not tell you which SUPABASE the build is pointed at.

Gotchas

  • git_sha is 'local' on a machine that did not run the stamp script. The committed placeholder src/lib/version.generated.ts exists so local type-checking works; a local next dev therefore reports local, and the promote verifier treats a null-ish sha as "do not roll back" rather than as a failure (scripts/deploy/verify-deployment.ts).
  • Verify on the PUBLIC custom domain, never on the *.vercel.app URL. Vercel SSO protection is all_except_custom_domains, so the staged URL answers 401 while app.dwelitics.com answers 200 — the whole reason the promote gate was redesigned in PHASE-157.
  • env is process.env.VERCEL_ENV ?? 'development' — so a local run reports development, not local.
